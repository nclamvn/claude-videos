## Prompt (tiếng Việt)

```text
Mẹo KHÔNG nằm ở prompt. Nó nằm ở một quy tắc: mọi khung hình là một hàm thuần của thời gian.

bài nhạc -> lưới nhịp bằng numpy -> Opus 5.5 viết một file HTML -> Playwright render -> ffmpeg trộn

bước 1 -> chọn một bài nhạc miễn phí bản quyền khoảng 120 BPM

bước 2 -> đưa cho Opus 5.5 từ 8 đến 12 trạng thái UI: button, loader, toggle, chart, command palette

bước 3 -> một file HTML, 1440x1440, mọi style được tính bên trong seek(t). không CSS transition, không timer

bước 4 -> lò xo dưới dạng toán nghiệm đóng, nên khung hình nào cũng render được theo thứ tự bất kỳ

bước 5 -> numpy tìm nhịp, mọi âm thanh UI rơi đúng vào một đỉnh đã đo

bước 6 -> Playwright chụp 4 khung phụ mỗi khung hình, ffmpeg tmix trộn chúng thành motion blur 60fps

bước 7 -> render một khung hình mỗi nhịp trước, sửa những gì lệch lưới, rồi mới render toàn bộ

phép tính:

120 BPM x 7 ô nhịp = 28 nhịp = 14 giây
14 s x 60 fps x 4 khung phụ = 3,360 lần render trên trình duyệt
```

## Prompt gốc

```text
The trick is NOT the prompt. It is one rule: every frame is a pure function of time.

song -> numpy beat grid -> Opus 5.5 writes one HTML file -> Playwright renders -> ffmpeg blends

step 1 -> pick a royalty-free track around 120 BPM

step 2 -> give Opus 5.5 8 to 12 UI states: button, loader, toggle, chart, command palette

step 3 -> one HTML file, 1440x1440, every style computed inside seek(t). no CSS transitions, no timers

step 4 -> springs as closed-form math, so any frame renders in any order

step 5 -> numpy finds the beats, every UI sound lands on a measured peak

step 6 -> Playwright shoots 4 subframes per frame, ffmpeg tmix blends them into 60fps motion blur

step 7 -> render one frame per beat first, fix what is off the grid, then the full render

the math:

120 BPM x 7 bars = 28 beats = 14 seconds
14 s x 60 fps x 4 subframes = 3,360 browser renders
```
